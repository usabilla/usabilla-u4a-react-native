# Usabilla React Native Sample App

This sample app demonstrates the Usabilla React Native SDK integration with support for multiple React Native versions and architectures.

## ⚡ Quick Start

```bash
# First time - generates native projects automatically
./.script/build-sample.sh

# Build with specific React Native version and architecture
./.script/build-sample.sh -v 0.76.11 -a legacy

# Build specific platform
./.script/build-sample.sh -p ios

# Clean build (recommended when switching major RN versions)
./.script/build-sample.sh -c

# Or use standalone clean script (no build)
./.script/clean.sh
```

**What this does:**
1. Installs dependencies
2. Generates fresh iOS/Android projects for specified RN version
3. Copies platform-specific assets (icons, emoticons, launch images)
4. Links fonts and images automatically
5. Builds and runs the app

**Note:** Use `./.script/clean.sh` to remove all generated files and caches without building. This is useful when:
- Switching between major React Native versions
- Clearing Metro bundler, Watchman, or CocoaPods caches
- Debugging build issues that might be cache-related

### Common Test Scenarios

```bash
# Test legacy architecture (older RN)
./.script/build-sample.sh -v 0.71.0 -a legacy -c

# Test modern with both architectures
./.script/build-sample.sh -v 0.76.11 -a legacy -c
./.script/build-sample.sh -v 0.76.11 -a turbo -c

# Test latest with TurboModules
./.script/build-sample.sh -v 0.83.4 -a turbo -c
```

### Script Options

| Option | Description | Default |
|--------|-------------|---------|
| `-v VERSION` | React Native version (0.61.5 to latest) | 0.83.4 |
| `-a ARCH` | Architecture: `legacy` or `turbo` | turbo |
| `-p PLATFORM` | Platform: `android`, `ios`, or `both` | both |
| `-c` | Clean build | false |
| `--skip-install` | Skip npm install | false |

### Version Quick Reference

- **0.61-0.63**: Legacy only, React 16
- **0.64-0.67**: Legacy + experimental Turbo, React 17
- **0.68-0.76**: Full legacy + Turbo support, React 18
- **0.77+**: Turbo recommended, React 18
- **0.83+**: Turbo only, React 19, needs Folly patch

## � Lean Structure Approach

This sample app uses a **lean repository structure** where native projects (`ios/` and `android/`) are **not committed** to version control. Instead, they are **automatically generated** by the build script based on the React Native version you specify.

### Benefits

- ✅ **No version conflicts**: Fresh native projects for each RN version
- ✅ **Smaller repository**: No large native project files in git (2.4 MB total)
- ✅ **Easy testing**: Test multiple RN versions without manual cleanup
- ✅ **Always up-to-date**: Native projects match the exact RN version
- ✅ **Minimal dependencies**: Only essential devDependencies (no testing/linting tools)
- ✅ **Focus on SDK**: Only files needed for SDK demonstration

### What's Included

**Committed to repository (12 essential files):**
- `App.tsx`, `index.js` - Sample app source code
- `assets/` - Fonts and images (268 KB)
- `platform-assets/` - iOS & Android assets: icons, emoticons, launch images (2.1 MB)
- `build-sample.sh` - Automated build script
- Essential configuration files:
  - `package.json` - Dependencies (minimal devDependencies)
  - `babel.config.js` - Babel transpiler  
  - `metro.config.js` - Metro bundler with symlink support
  - `react-native.config.js` - Asset linking
  - `tsconfig.json` - TypeScript
  - `app.json` - App metadata
  - `.gitignore` - Git exclusions
- `README.MD` - Documentation

**Auto-generated by build script (not in repo):**
- `ios/` - iOS project (from React Native template)
- `android/` - Android project (from React Native template)
- `node_modules/` - npm dependencies
- `Pods/` - CocoaPods dependencies
- `package-lock.json`, `Gemfile.lock` - Lock files

**Excluded (keep repo lean):**
- `Gemfile` - Ruby bundler (CocoaPods installed globally)
- `.eslintrc.js` - ESLint config (optional dev tool)
- `.prettierrc.js` - Prettier config (optional dev tool)
- `.watchmanconfig` - Watchman config (uses defaults)
- `jest.config.js`, `__tests__/` - Testing files (not needed for demo)
- Jest, ESLint, Prettier devDependencies removed from package.json

### How It Works

1. Build script checks if `ios/` or `android/` folders exist
2. If missing, creates temporary RN project with specified version
3. Copies native folders from temp project to sample app
4. **Copies platform-specific assets** (app icons, emoticons, launch images)
5. Links assets (fonts, images) automatically
6. Applies architecture configuration (legacy/turbo)
7. Builds the app

## 🛠️ Build Script Options

The `build-sample.sh` script provides a comprehensive way to test the SDK across different React Native versions and architectures.

### Usage

```bash
./.script/build-sample.sh [options]
```

### Options

| Option | Description | Default |
|--------|-------------|---------|
| `-v, --version VERSION` | React Native version (0.61.5 to latest) | 0.83.4 |
| `-a, --arch ARCH` | Architecture: `legacy` or `turbo` | turbo |
| `-p, --platform PLATFORM` | Platform: `android`, `ios`, or `both` | both |
| `-c, --clean` | Clean build (removes node_modules, pods, build artifacts) | false |
| `--skip-install` | Skip npm install | false |
| `-h, --help` | Show help message | - |

### Examples

```bash
# Test with React Native 0.83.4 and TurboModules (New Architecture)
./.script/build-sample.sh

# Test with React Native 0.76.11 and legacy architecture
./.script/build-sample.sh -v 0.76.11 -a legacy

# Build only Android with React Native 0.75.0
./.script/build-sample.sh -v 0.75.0 -p android

# Clean build with React Native 0.72.0
./.script/build-sample.sh -v 0.72.0 -c

# Test latest version on iOS only
./.script/build-sample.sh -v 0.83.4 -p ios

# Quick rebuild without reinstalling dependencies
./.script/build-sample.sh --skip-install
```

## 🏗️ Architecture Types

### Legacy Architecture (Pre-TurboModules)

The traditional React Native architecture using the old bridge system.

```bash
./.script/build-sample.sh -a legacy
```

**Pros:**
- Stable and well-tested
- Compatible with older React Native versions
- No additional configuration needed

**Cons:**
- Slower performance
- Higher memory usage
- Limited type safety

### New Architecture (TurboModules)

Modern React Native architecture with improved performance and type safety.

```bash
./.script/build-sample.sh -a turbo
```

**Pros:**
- Better performance
- Improved type safety with TypeScript
- Lower memory footprint
- Direct JSI integration

**Cons:**
- Requires React Native 0.68+
- May need platform-specific patches for some versions
- Some third-party libraries may not be compatible

## 🔧 Manual Build

If you prefer to build manually without the script:

### Android

```bash
# Install dependencies
npm install --legacy-peer-deps

# Enable TurboModules (optional)
echo "newArchEnabled=true" >> android/gradle.properties

# Run Android
npm run android
```

### iOS

```bash
# Install dependencies
npm install --legacy-peer-deps

# Install pods
cd ios && pod install && cd ..

# Run iOS
npm run ios
```

## 🐛 Troubleshooting

### React Native 0.83.x iOS Build Issues

React Native 0.83.x has known issues with Folly coroutines on iOS. The build script automatically applies a patch, but if you encounter errors:

1. The error typically shows: `'folly/coro/Coroutine.h' file not found`
2. The script patches this automatically in `post_install` hook
3. If issues persist, run with `-c` flag for a clean build

### Android Build Failures

```bash
# Clean gradle cache
cd android && ./gradlew clean && cd ..

# Clean build
./.script/build-sample.sh -c -p android
```

### iOS Build Failures

```bash
# Clean pods and derived data
rm -rf ios/Pods ios/Podfile.lock
rm -rf ~/Library/Developer/Xcode/DerivedData/RNUsabilla-*

# Reinstall
cd ios && pod install && cd ..

# Or use clean build
./.script/build-sample.sh -c -p ios
```

### Metro Bundler Issues

```bash
# Clear Metro cache
npm start -- --reset-cache

# Or
watchman watch-del-all
rm -rf $TMPDIR/metro-* $TMPDIR/haste-*
```
